# おはようペット / CotzCotz — Google広告 販促パッケージ

作成日: 2026-08-09 ／ 対象: Google アプリキャンペーン（静止画のみ運用を前提）
前提資料: `ohapet` / `cotzcotz` / `app-ads` の全ソース・仕様書を精読して作成

---

## 0. 最初に結論だけ

| 論点 | 結論 |
|---|---|
| 静止画だけで戦えるか | **戦える。** アプリキャンペーンで画像・動画はどちらも「任意」で、必須はテキストのみ |
| ただし最大の落とし穴 | **自分の動画を1本も入れないと、Google がストア情報から自動生成動画を勝手に作って配信する。** アプリキャンペーンにはオプトアウトのトグルが無く、公式に示された唯一の停止方法は「自分の動画をアップロードすること」 |
| その対策 | **静止画をつないだ13秒のスライドショー動画を、この納品物に含めました**（撮影も編集も不要。YouTubeに限定公開でアップして貼るだけ） |
| P-MAX は使うか | **使わない。** P-MAX は「アプリインストール」を目標にできない（公式明記）。Demand Gen も同様。アプリ訴求は**アプリキャンペーン一択** |
| キャンペーン構成 | **アプリごとに1キャンペーン・1広告グループ。** 同一アプリ・同一地域で複数キャンペーンを走らせない（自社競合になる） |
| 画像内にロゴを入れるか | **入れない。** アプリキャンペーンはストアのアイコン・スクショ・タイトルを自動で素材化するので、画像にロゴを重ねる必要がない。むしろ重ねると配信面が狭くなる |
| 予算の下限式 | **日予算 ≧ 目標インストール単価 × 50。** ここを外すと学習が回らない（最重要） |

## 1. 二つのアプリの「本当の売り物」— コードから読み取った潜在価値

宣伝文句を作る前に、実装を読んで「このアプリが他と違う点」を確定させました。ここが全クリエイティブの土台です。

### 1-1. おはようペット

| 実装されている事実 | 広告での意味 |
|---|---|
| 就寝（消灯）と起床（アラーム停止）だけで育成が進む。寝る前の長い操作が要らない | **Pokémon Sleep の最大の不満「寝る準備より先にアプリ操作が要る／端末が熱い」の裏返し。「手間の軽さ」が最強の差別化** |
| 睡眠を R/F（規則性）・D/L（質）・M/N（朝型夜型）・A/P（即起き/二度寝）の4軸で評価し、Day4で4系統、Day8で8形態＋レア8種に分岐 | 「あなたの起き方で姿が変わる」＝**自分ごと化**。ガチャではなく行動の結果なので納得感がある |
| レアは「Day1〜7を1日も落とさずR かつ A」でのみ到達 | **「完璧な朝を続けた人だけが会える姿」**という強い動機。ただし広告で断定しすぎない（誇大表現の審査リスク） |
| 曜日別繰り返し・スヌーズ・スライドで停止・iOS AlarmKit / Android AlarmManager 統合。育成をやめて純アラームとして使う「アラームモード」もある | **「まず目覚ましとして優秀」**という土台の訴求。Alarmy の「起きられるがつらい」層の受け皿 |
| ウィジェット（iOS/Android両方）、天気表示、おるすばんモード（1日1回・最大12時間） | 「毎日開かなくていい」＝継続のハードルが低い |
| 飼い主生態診断（16タイプ）＋ SNS シェア画像生成 | **バイラルの種**。広告でも「診断」訴求はクリック理由になる |
| 多言語（日・英・中簡繁・韓・西・仏・独）実装済み | 将来の海外展開。**ただし初動は日本語・日本のみに絞る**（後述） |

**取るべきポジション** — 「**起こしてくれるのに、憎めない目覚まし**」
競合の空白は明確です。Alarmy は「確実に起きられるが、ストレスがかかる」。Pokémon Sleep は「楽しいが、寝る前の操作が重い」。**「操作が軽い」×「起きるのが楽しみになる」**の象限が空いています。

### 1-2. CotzCotz

| 実装されている事実 | 広告での意味 |
|---|---|
| 目標カードが4タイプ（毎日型 / 回数型 / ペース型 / やりとげる型） | 宿題も習い事もテスト勉強も1本で扱える＝**「うちの子の場合」に必ず当てはまる** |
| 見守り＝親のスマホと子のスマホで同じカードを共有し、確認スタンプ＋ひとことで応援。Firestore 同期・招待コード・QR | **ここが最大の構造的優位。** 無料圏の競合（おてつだいノート等）はローカル保存のみで、最頻出の要望が「共有機能をつけてほしい」 |
| 「おやすみ（skip）」で連続を切らさない。期限未達でも労って締める | **「できなかった日を責めない」**。継続アプリで最も刺さる思想的差別化 |
| レアリティ8段階（3日「三日坊主 こえた！」→ 365日「1年 ヒーロー」→ 1095日「3年 ゴッド」）。連続ではなく**累計**なので休んでも下がらない | 「三日坊主をこえた」は**コピーとしてそのまま強い**。実装の言葉がそのまま広告になる稀なケース |
| コツコツ遊園地（通算Cotzで11アトラクションと7ステージが自動解放。砂場→海賊船のようにスロットが「昇格」する） | 子ども本人への訴求はこれ一本で足りる |
| 年齢に応じてひらがな／漢字を自動で出し分け（`K()` / `labelOf()`） | 未就学〜低学年でも本人が読める＝**「子どもが自分で使える」**の裏づけ |
| 子どもアカウントは課金導線ゼロ（`canMonetize` は guardian のみ＋保護者確認） | 親の不安を消す。**安心設計は広告文に入れる価値がある** |
| 目標カードの追加は無料（★200 廃止）。ウィジェット iOS/Android 両対応 | 「きょうだいの分も無料」が言える |

**取るべきポジション（親）** — 「**怒らなくてよくなる、家族の習慣アプリ**」

検索データが決定的です。「子供 勉強しない」のサジェスト上位は **ストレス / イライラ / 疲れた**。買うのは親で、痛いのは親の感情です。にもかかわらず既存アプリの訴求は全て機能語（「当番表・チェック表・お小遣い帳」）で、**感情に触れているアプリが1本もありません**。ここが最大の空白です。

**第2の柱（働く親 × 留守番している子ども）** — 「**同じ家にいなくても、同じ1日を見られる**」

これは CotzCotz が持つ機能のうち、**もっとも情緒的で、もっとも競合が持っていない**部分です。実装を確認すると:

- `sendGift` / `watchGiftsForMe` / `bulkApproveForMe` / 招待コード・QR による見守り接続 — **親のスマホと子のスマホは別端末でよく、Firestore 経由でリアルタイムに同期する**
- 子どもの記録は**承認を待たずに即座にバー・スタンプへ反映**される（＝親が見ていなくても子は進める）
- 親は手が空いたときに「確認したよ」スタンプ＋ひとことを返すだけ。**同期的なやりとりを強制しない**
- ウィジェット「確認待ち」— 親はアプリを開かなくても、返すべき応援があることに気づける

つまりこの機能は、**「働いていて家にいられない親」と「留守番している子ども」のための非同期のコミュニケーション装置**として設計されています。宿題を終えた子が記録する → 会社にいる親のスマホに届く → はなまるが返る。**帰宅して確認して叱る、という一日の終わり方を、日中の小さな承認に置き換えられる。**

無料圏の競合（おてつだいノート等）はローカル保存のみで、最頻出の要望が「共有機能をつけてほしい」。有料圏のみんチャレは他人とのチーム。**「離れて暮らす／離れて働く家族の、あたたかい非同期の承認」は完全に空いています。**

**もう一つの空白（恋人・友だち）** — 日本語圏のカップルアプリ（Between 5.8万件、The Couple 6,427件、COUPPLY 597件）は全て「記念日・アルバム・共有カレンダー」訴求で、**「二人で習慣を続ける」を主訴求にしたアプリが見当たりません**。みんチャレの効き目（相互監視）を、みんチャレの最大の不満（見知らぬ他人のストレス）なしで提供できる — これが CotzCotz の見守り機能の別解釈です。
ただし「カップル 習慣」「夫婦 目標 共有」は**検索需要が枯れている**ので、**検索では取れず、広告で作りにいく市場**です。だから静止画クリエイティブでの出し分けが効きます。

## 2. なぜ「クリエイティブ＝ターゲティング」なのか（最重要の設計思想）

**アプリキャンペーンにはオーディエンス指定がありません。** 年齢・興味関心・キーワードで絞ることができず、Google の自動入札が全て決めます。

つまり **「小学生以下の子を持つ親」「小学生以上の子ども本人」「中学生以上の恋人たち」を分けて狙う唯一の手段が、クリエイティブそのもの**です。

- 親向けの画像に反応した人 → Google は「親っぽいユーザー」に配信を寄せる
- 子ども向けの絵と ひらがな に反応した人 → そちら側へ寄る
- 二人の Cotz とスタンプの絵に反応した人 → その層へ寄る

だから **1つの広告グループに3セグメント分のクリエイティブを共存させ、機械に選ばせる**のが正解です。セグメントごとにキャンペーンを割ると、少額予算では全部が学習不足になります。

## 3. キャンペーン設計

### 3-1. 構成

| 項目 | おはようペット | CotzCotz |
|---|---|---|
| キャンペーン種別 | アプリキャンペーン（インストール数） | アプリキャンペーン（インストール数） |
| 広告グループ | 1つ | 1つ |
| 地域 | 日本のみ | 日本のみ |
| 言語 | 日本語のみ | 日本語のみ |
| 入札 | 目標インストール単価（tCPI） | 目標インストール単価（tCPI） |
| OS | まず **Android から**（後述） | まず **Android から** |

**なぜ日本のみか**: 広告文は翻訳されません。かつ地域を絞るほどオークション密度が上がり、少額でも学習が回ります。おはようペットは多言語対応済みですが、**海外展開は日本で数字が出てから**。

**なぜ Android からか**: iOS はカジュアル系で 30日 ROAS が高い一方、SKAdNetwork の計測制約でシグナルが薄く、少額では学習が遅れます。Android はインストール単価が安く、コンバージョンが早く貯まります。**まず Android で「効くクリエイティブ」を確定させ、それを iOS に持っていく**のが低予算の定石です。

### 3-2. 予算 — ここだけは絶対に外さない

Google の公式ガイドは **「アプリキャンペーン（tCPI）の日予算は目標CPIの50倍」**です。逆算するとこうなります。

| 月予算 | 日予算 | 成立する目標CPI（上限） |
|---:|---:|---:|
| 3万円 | 1,000円 | 20円 ← 非現実的 |
| 5万円 | 1,650円 | 33円 ← ほぼ非現実的 |
| **10万円** | **3,300円** | **66円** ← Android・日本のみなら射程 |
| 15万円 | 5,000円 | 100円 ← 現実的 |
| 30万円 | 10,000円 | 200円 ← iOS も含めて現実的 |

**推奨**: 最初の1ヶ月は **1アプリに集中して月10〜15万円**。2アプリに5万円ずつ割ると、両方とも学習が回らずに終わります。

どちらを先に出すか — **おはようペットを先に**。すでに App Store で公開済みでレビューも付いており（4.2）、ストア素材（7枚構成のスクショ・ASOメタデータ）が整っているためです。CotzCotz は `docs/PROJECT_STATE.md` の残作業（実機確認、IAP登録、AdMob本番化、データセーフティ入力）が片付き、ストア掲載情報が仕上がってから。**ストアのスクショは自動で広告素材になるので、ASO が未完成のまま広告を回すのは予算をドブに捨てるのと同じです。**

### 3-3. 計測（配信前に必須）

- Firebase（Google Analytics for Firebase）を両アプリに導入し、**インストール ＋ 最低1つのアプリ内イベント**を計測できる状態に。
  - おはようペット: `alarm_stopped`（初回の起床成功）／`pet_hatched`（孵化＝Day1到達）
  - CotzCotz: `first_cotz`（初回記録）／`connect`（見守り接続）
  - **どちらも、そのイベントを「継続の予兆」として選ぶこと。** インストール直後ではなく1〜3日目に起きるイベントが良い指標になります。
- iOS を出すときは SKAdNetwork の設定も。
- 初期はコンバージョン遅延で CPI が高く見えます。**ビュースルーを含めた調整後CPIで判断**してください。

### 3-4. 運用ルール（守らないと機械学習が壊れる）

| ルール | 数値 |
|---|---|
| 配信開始後、触らない期間 | **7〜14日** |
| 次の入札変更までに必要なCV数 | **最低100件** |
| 1日あたりの変更幅 | **予算・入札とも20%以内** |
| キャンペーンタイプの変更 | **不可**（インストール数 ⇄ アプリ内アクションは後から変えられない。作り直しになる） |
| クリエイティブ差し替え | 週次で「低」評価を確認 → 月次でまとめて入替。**一度に全部替えない** |

## 5. 自動生成動画への対処 —「動画が作れない」問題は解決済み

**問題**: アプリキャンペーンで自分の動画を1本も入れないと、Google が App Store / Google Play の掲載情報から**自動生成動画**を作り、Google 所有の YouTube チャンネルに置いて配信します。広告主はその中身を編集できません。**アプリキャンペーンには停止トグルが無く、公式に案内されている唯一の停止方法は「自分の動画をアップロードすること」**です。

**解決**: 撮影も編集も不要な **静止画スライドショー動画（13秒）** を作って同梱しました。納品済みの静止画をクロスフェードでつないだだけのもので、内容は全て事実ベース、審査リスクのある表現は含みません。

```
video/ohapet_slideshow_1x1.mp4     1200x1200 / 13秒
video/ohapet_slideshow_9x16.mp4    1080x1920 / 13秒
video/cotzcotz_slideshow_1x1.mp4   1200x1200 / 13秒
video/cotzcotz_slideshow_9x16.mp4  1080x1920 / 13秒
```

**使い方**
1. YouTube に**限定公開**でアップロード（一般公開でなくて構いません）
2. Google 広告 → 該当の広告グループ → アセット → 動画 → YouTube の URL を貼る
3. これで自動生成動画は無効化され、Ad Strength も上がります

※ 静止画のみのままでは、Ad Strength は「動画アセットの追加」を推奨し続けるため構造的に上限が抑えられます。最低ライン「良（Good）」を狙う運用になります。動画を1本入れるだけでこの制約が外れます。

## 7. ASO（ストア掲載情報）— 広告と同じくらい重要

**アプリキャンペーンは、ストアから7種類の素材（アプリ動画・カバー写真・スクリーンショット・簡単な説明・タイトル・アイコン・デベロッパー名）を自動で取得して広告に使います。** つまり **ASO ＝ 広告クリエイティブ制作そのもの**です。ここを直さずに広告画像だけ磨いても効果は限定的です。

### 7-1. おはようペットのストア掲載情報 — 提案する変更

現行のサブタイトルは「目覚まし時計で可愛いペットを育成！」で、これは**機能説明**であり、悩みに接続していません。一方、説明文の冒頭「ただのアラームじゃ起きられない、朝が苦手……」の方が圧倒的に強い。**こちらをサブタイトル側に上げるべき**です。

| 項目 | 現行 | 提案 |
|---|---|---|
| App Store サブタイトル（30字） | 目覚まし時計で可愛いペットを育成！ | **朝が苦手でも起きられる｜育成アラーム** |
| Google Play 簡単な説明（80字） | 起きるのが楽しみに！毎日の睡眠リズムを… | **朝が苦手な人のための目覚まし。設定したアラームで起きると、かわいいペットが育ちます。曜日別アラーム・スヌーズ・ウィジェット対応。** |
| キーワード（100字） | 目覚まし,アラーム,睡眠,ペット,育成,… | **絶対起きる** / **起きれない** / **二度寝** / **ミッション** を追加（実際に検索されている語） |

根拠: Google サジェストの実データで「目覚まし アプリ」の上位に **絶対起きる（4位）/ 計算（6位）/ ミッション（7位）** が入っています。逆に「アラーム アプリ かわいい」「育成 アプリ 目覚まし」は**サジェストが枯れており検索需要が薄い**。
→ **検索は「絶対起きる」「起きれない 対策」で取り、かわいさはスクショと広告で見せる**という役割分担が正解です。

### 7-2. CotzCotz のストア掲載情報 — 提案

| 項目 | 提案 |
|---|---|
| App Store サブタイトル（30字） | **お手伝い・宿題をポイントで習慣化｜家族で共有** |
| Google Play 簡単な説明（80字） | **「勉強しなさい」を言わずにすむ毎日へ。子どもの習慣を家族で見守るアプリ。親のスマホと子のスマホで共有、スタンプで応援できます。** |
| スクショ1枚目 | **「勉強しなさい」を、言わなくてよくなる。** ＋ ホーム画面（＝`COTZ-P1` と同じ文言に揃える） |

実需のある語（**ポイント / 共有 / 習慣化 / お手伝い**）を全部入れる。とくに「お手伝い **ポイントアプリ 共有**」「習慣化 アプリ **共有**」はサジェストに実在します。

### 7-3. Google Play カスタムストアリスティング（Android のみ・任意）

Play Console で「Ads Traffic」をターゲットにしたカスタムストアリスティングを作り、Google 広告の AdGroupID を紐付けると、広告経由の訪問者だけに専用のスクショ・説明文を出せます。
**制約**: 広告向けカスタムリスティングは現状 **AdMob ネットワーク面にのみ表示され、Google Play 検索広告は対象外**です。効果範囲は限定的なので、**優先度は中**。まずは通常の掲載情報を仕上げるのが先です。

### Month 2 — 拡張

- ※ キャンペーンタイプ（インストール数 ⇄ アプリ内アクション）は既存キャンペーンでは変更できません。**新規キャンペーンを作る**ことになるので、Android の数字が十分に貯まってから

4. アプリ内イベント（起床成功／初回記録）の発生率 ← **これが本当の質**

## 9. さらに踏み込んだ提案（予算をかけずにできること）

### 9-1. おはようペットの「診断結果シェア」を広告代わりに使う

`飼い主生態診断` は結果を1枚のポスター画像として生成し、インストールリンク付きで SNS シェアできる実装がすでにあります。これは **費用ゼロの獲得チャネル**です。

- **シェア画像に「あなたは何型？」の余白を入れて、受け手が試したくなる形に**（今の実装は結果表示が主）
- ペットが天寿を全うしたときだけでなく、**Day 8（アダルト進化）でも中間診断としてシェアできる**ようにすると、シェア発生数が数倍になります（現状は最後まで育てないと出ない＝発火が45日後）
- 「#おはペット診断」のような統一タグを画像に焼き込む

### 9-2. CotzCotz は「三日坊主」をブランドワードにする

コード内のランク称号「**三日坊主 こえた！**」は、そのまま広告コピーとして強い言葉です。ストア説明文・スクショ・広告見出しの全てで一貫して使い、**「三日坊主をこえるアプリ」**として記憶させることを推奨します。競合（みんチャレ）が「三日坊主を卒業しよう」を使っていますが、**あちらは他人とのチーム、こちらは家族**という明確な差があります。

### 9-2b. 「働く親 × 留守番の子」を、アプリ内の体験としても強化する

広告でこの物語を語るなら、アプリ側にも受け皿があるほど強くなります。実装済みの機能を少し延ばすだけでできる提案です。

- **「おかえり通知」**: 子が下校後に初めて記録した瞬間、親へプッシュ。「〇〇さんが『毎日ドリル2ページ』を記録しました」＝**親にとっては「無事に帰って、やることをやった」という安心の通知**でもある。実装は `schedulePush()` の延長線上
- **確認スタンプに「時刻」を添える**: 子の画面に「17:42 おかあさんが見てくれた」と出す。**非同期でも「見てもらえた瞬間」が可視化される**のが、この機能の情緒的な核心
- **ウィジェット「確認待ち」を親の帰り道に効かせる**: 既に実装済み。通勤中に開かなくても気づける状態は、この訴求の裏づけそのもの
- 広告→ストア→初回体験の一貫性: スクショ2枚目に **`COTZ-P5_far` と同じ「会社にいても、『できたね』は届く。」**を置く

### 9-3. 二人向けは「広告で作る市場」

「カップル 習慣」は検索需要が枯れています。したがって**検索では取れません**。取るなら:

- Demand Gen（YouTube ショート面・Discover 面）で `COTZ-C1` `COTZ-C2` を配信し、**LP（rhythmap.net/cotzcotz/lp/）へ送客** → そこからストアへ
- ※ Demand Gen は「アプリインストール」を最適化目標にできないため、**認知・サイト訪問の用途に限定**すること。インストール数を直接最適化したいならアプリキャンペーンのまま、クリエイティブで寄せるのが正解

### 9-4. 「かんたんめざまし」からの送客

同じ RHYTHMAP の `かんたんめざまし` は既に Play で配信中です。**そのユーザーは定義上「目覚ましアプリを使う人」**であり、おはようペットの最良の見込み客です。アプリ内に小さな相互送客導線（もしくは AdMob のハウス広告）を置くのは、CPI ゼロの獲得になります。

### 9-5. 静止画で勝ってから動画を増やす

「当たった静止画にちょい足しでアニメを付ける」が、動画制作の最も安い入口です。今回のスライドショーはその第一歩です。Week 4 時点で「最良」評価だった静止画だけを使って2本目のスライドショーを作れば、それが最も費用対効果の高い動画になります。**先に動画を作り込むのは順番が逆です。**

### 9-6. やらないことリスト

- P-MAX でアプリインストールを狙う（**公式に非対応**）
- Demand Gen でインストール数を最適化する（**目標として非対応**）
- 同一アプリ・同一地域で複数のアプリキャンペーンを並走させる（自社競合）
- 地域・プレースメントの除外を増やしすぎる
- 学習期間中に予算・入札をいじる
- スクリーンショットをそのまま全画面で画像アセットにする（オーバーレイ判定とクロップ事故のリスク）
- 画像に「ダウンロード」「インストール」の文字を入れる（**自動不承認**）
